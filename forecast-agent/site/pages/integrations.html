Integrations

Connect once. Fresh forecasts every morning.

Draxly pulls your sales, and stock on hand where your system has it, every night at about 2 a.m. in your time zone. It uses read access only, and credentials are encrypted at rest.

Sales through SuiteQL over NetSuite's REST web services, using token-based authentication.

SalesToken-based auth

Your admin creates an integration record and an access token for a role with read access.

SAP

SalesOData

SalesMicrosoft Entra app

Any other system

Secure API and HTTPS file drop

If your system isn't listed, it can still feed Draxly. Each method uses API keys that an admin creates, with their own permissions.

REST API

Send sales and stock levels as JSON, and read forecasts and reorder suggestions back.

POST /v1/sales · POST /v1/inventory · GET /v1/forecasts · GET /v1/reorder

HTTPS file drop

Have your scheduler send a CSV export to POST /v1/files, up to 20 MB per file. Columns are recognized the same way as an upload.

SFTP isn't offered. Most schedulers that drop files over SFTP can also send them to this HTTPS endpoint.

Nightly file from a web address

Point Draxly at a CSV export published at an HTTPS address, such as a SharePoint, OneDrive, S3 or Azure link, or your own server. Draxly fetches it every night.

curl -X POST __SITE_URL__/v1/files \
  -H "Authorization: Bearer $DRAXLY_KEY" \
  -H "Content-Type: text/csv" --data-binary @sales.csv

Setup

How a connection is set up

  • An admin opens Connections in Draxly and picks the system.
  • They enter the details your IT team provides. Step-by-step instructions are shown for each system.
  • "Test connection" checks the details before the first sync.
  • The first sync pulls your history; after that, Draxly syncs every night.

Read access only. Draxly only reads sales and stock. Ask your administrators to give the connection read-only access.

Each connector is built to the vendor's published API. Because every company's setup is different, we confirm each connection with you during onboarding, ideally against a sandbox or test company first.
