Security

An overview for IT and security teams of how Draxly protects your data. It describes what the service actually does today.

Where it runs

The service runs on Cloudflare (Workers and Durable Objects). Every connection uses HTTPS, and browsers are told to use HTTPS only (HSTS). The app's pages use a strict Content Security Policy, and no third-party scripts are loaded.

Each company's data is kept apart

  • Each company's sales, forecasts, stock levels, connections and activity log live in that company's own separate storage object, never in a shared table.
  • Every request works out its company from the signed-in session or API key, never from anything the browser or caller names. Asking for another company's records by their ID returns "not found". This is covered by our automated tests.

Encryption

  • In transit: HTTPS (TLS) for every request, including the connections we make to your systems.
  • At rest: sales figures, product, store and region names, forecasts, accuracy results, stock levels, connection credentials and two-factor secrets are encrypted by the application with AES-256-GCM before they're stored. The key is held in Cloudflare's secret store, separate from the data.
  • Some details are stored without application-level encryption because the service needs to search or display them directly: company names, user names and email addresses, upload names, and activity-log entries.
  • When you upload a spreadsheet, it's read in your browser. Only monthly totals are sent; the file itself never leaves your computer.

Signing in

  • Single sign-on with Microsoft (Entra ID) and Google, using OpenID Connect with PKCE. ID-token signatures, issuer, audience, expiry and a one-time nonce are all checked.
    • For Microsoft we rely on the tenant-verified sign-in name, not the editable email claim.
    • For Google, only verified emails are accepted.
    Admins can require single sign-on for everyone, and choose which email domains may join automatically (as viewers).
  • Two-factor sign-in with any authenticator app (TOTP, RFC 6238). Each user gets one-time backup codes. Admins can require two-factor for everyone.
  • Passwords are stored only as salted PBKDF2-SHA256 hashes. The work factor is currently 5,000 rounds, set by the hosting plan's processing limit; it moves to 600,000 rounds on the production plan, and existing users are upgraded at their next sign-in.
  • Limits on guessing:
    • After 5 wrong passwords, two-factor codes or recovery codes, that account waits 15 minutes.
    • Wrong answers look the same whether or not an account exists.
    • Password reset links and invites are single-use and expire after 24 hours and 7 days respectively.
    • Only hashes of reset links and invites are stored.
  • Sessions are random 256-bit tokens that last 30 days. Admins can switch a user off, which ends their sessions immediately, or sign everyone else out at once.

Roles

Three roles, enforced on the server for every request:

  • Viewer: can see forecasts, stock and reports.
  • Manager: can also upload data, run forecasts and manage stock levels.
  • Admin: can also manage the team, security settings, connections, API keys and the activity log.

Every company always keeps at least one admin.

Activity log

Every sign-in (successful or failed), change to users, roles or security settings, upload, deletion, forecast, connection change, sync, API call that changes data, API key change, and email sent is recorded. Each entry shows who, when and from which IP address. Admins can view and download the log; it's kept for the life of the account.

API and connections

  • API keys are shown once and then stored only as SHA-256 hashes.
    • Each key has its own permissions: send sales, send stock, read forecasts.
    • Each key is limited to 120 calls a minute.
    • Keys can be revoked at any time.
  • Credentials for connected systems (NetSuite, SAP, Dynamics 365, QuickBooks, Shopify, Square) are encrypted at rest and used only to read sales and stock. Ask your administrators to grant read-only access.

Other services we use

  • Cloudflare: hosting, storage and secrets.
  • Resend: sending email (invites, invoices and payment reminders, weekly reports, low-stock alerts), when email is switched on.
  • Microsoft and Google: single sign-on, when you use it.
  • ntfy.sh: the platform operator's phone alerts. When someone asks for a password reset link, the alert contains their company name and email. When someone requests access from the demo, it contains the name, company and email they entered.
  • The systems you connect, which we contact on your behalf.

The open demo

The demo at /demo needs no sign-up and shows no sample data. A visitor's spreadsheet is read in their own browser. Only monthly totals per product are sent to Draxly, in small batches, to be forecast in memory and sent straight back. They're never stored, so no one else (including us) can see them later. The results exist only in the visitor's open page and are gone when they close it or press “Start over”.

For each forecast run we record the time, the approximate city and country (from Cloudflare's view of the visitor's network), the type of device, the page that linked to the demo, and the size of the file (number of products and months). We don't record IP addresses, sales figures or product names. If a visitor fills in “Request access”, what they type is stored and sent to us.

Deleting data

Admins can delete any upload. When an account is closed, all of that company's stored data is deleted: sales, forecasts, stock, connections, the activity log, users and API keys.

Certifications

We don't currently hold SOC 2 or ISO 27001 certification. We're happy to answer your security questionnaire.
